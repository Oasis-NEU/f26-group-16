# Auth setup (Supabase Auth)

Login and sign-up use Supabase Auth instead of storing our own password hashes. Supabase hashes and checks passwords on the server, keeps the user logged in across reloads, and handles logout, so the browser never needs to read `pwd_hash`.

Users sign up and log in with their own email and a password. Each account still gets a random 10-digit `uid` in our `users` table (generated by the app), so `events.organizer_uid` and `joined_events.joiner_uid` work as before.

Someone with access to the Supabase project needs to do the two steps below once.

## 1. Dashboard setting

Authentication → Sign In / Providers → **Email**:

- Email provider: **on**
- Confirm email: **off for now**. Supabase's built-in email service only delivers to members of the Supabase project and sends just a few emails per hour, so classmates would never get the link. Turn it back on once we set up our own email sender (Authentication → Emails → SMTP Settings). The app already handles both: with it on, sign-up shows "Check your inbox".

## 2. SQL (run in the SQL Editor)

```sql
-- Link each profile row to its Supabase Auth account.
ALTER TABLE users ADD COLUMN auth_id UUID UNIQUE REFERENCES auth.users(id) ON DELETE CASCADE;

-- Passwords now live in Supabase Auth. (As of 11/1 the live table already has no pwd_hash.)
ALTER TABLE users DROP COLUMN IF EXISTS pwd_hash;

-- Create the `users` row automatically when someone signs up.
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER SET search_path = ''
AS $$
BEGIN
  IF coalesce(new.raw_user_meta_data->>'uid', '') !~ '^[0-9]{10}$' THEN
    RAISE EXCEPTION 'uid must be 10 digits';
  END IF;
  IF coalesce(trim(new.raw_user_meta_data->>'full_name'), '') = '' THEN
    RAISE EXCEPTION 'full_name is required';
  END IF;

  INSERT INTO public.users (uid, full_name, is_active, auth_id)
  VALUES (new.raw_user_meta_data->>'uid', trim(new.raw_user_meta_data->>'full_name'), true, new.id);
  RETURN new;
END;
$$;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();

-- Logged-in users can read profiles (names on events, comments, chats)
-- and edit only their own.
ALTER TABLE users ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Logged-in users can read profiles"
  ON users FOR SELECT TO authenticated USING (true);

CREATE POLICY "Users can update their own profile"
  ON users FOR UPDATE TO authenticated
  USING (auth_id = auth.uid()) WITH CHECK (auth_id = auth.uid());
```

## How the app uses it

All in `src/api.jsx`:

| Function | What it does |
|---|---|
| `generateUid()` | Random 10-digit `uid` for the `users` row (called inside `signUp`) |
| `signUp({ email, fullName, password, confirmPassword })` | Validates, then creates the account. The trigger above creates the `users` row. |
| `logIn(email, password)` | Logs in. The session is saved in the browser until logout. |
| `logOut()` | Logs out (for the account settings popup) |
| `onSessionChange(callback)` | Lets `App.jsx` switch between the login page and the app |
| `getProfile(authId)` | The `users` row for the logged-in account |

If `is_active` is false, `App.jsx` logs the user straight back out and shows "This account has been deleted."

## Troubleshooting

- **"Database error saving new user"**: the trigger failed. Check that step 2 ran, and that `users` has no other `NOT NULL` column the trigger doesn't fill.
- **Sign-up says "Check your inbox" but no email arrives**: Confirm email is still on (step 1).
- **"Email address … is invalid"**: Supabase rejects domains that can't receive mail (e.g. `example.com`, `test.local`). Use a real address.
